# 验收与真实联调

## 自动化层

核心测试与 Windows 模拟进程测试通过情况以 `docs/TEST_RESULTS.md` 为准。测试不会触发真实游戏任务。

## 用户界面手动验收

这些操作由用户执行，开发代理不代为点击、输入或修改系统设置：

1. 在全新解压目录启动 GameRelay，确认中文页签、正常上限 3、保护上限 1、没有活动计划。
2. 打开脚本页扫描并取消，确认界面可响应、新发现项停用；别名不改变原目录。
3. 开启鸣潮保护，彻底退出后重新打开，确认开关保留；无鸣潮进程时不会自行关闭。
4. 点窗口关闭，确认托盘仍存在；托盘打开、暂停/恢复、彻底退出可用。
5. 编辑计划、取消保存、多选批量计划、筛选记录、中文和空格路径分别检查。
6. 检查缩放、多显示器、系统通知关闭/开启情况下的体验。

## 真实联调边界

真实联调必须在列出对象、所用配置、预计运行内容、启动/清理步骤和影响后取得授权。当前未执行真实游戏、脚本或模拟器启停，也没有修改原配置。

建议顺序：先用一个已确认绑定的普通实例完成一次正常运行；确认自动开始、完成动作与资源释放；再验证两个独立实例，最后验证五账号三组补位。异常强制清理只在专门授权的测试轮次中执行。备用 BD2/AALC 默认停用，不操作 VMware 或虚拟机。

对真实任务授权时应明确：是否允许当前所选原脚本任务实际执行、是否允许启动对应游戏/模拟器、是否允许对这一轮进行超时清理测试。任务内容、次数、体力等仍由原脚本配置决定。

真实验收分别记录：启动参数成功接收、任务确实开始、账号/目标未串用、普通限制/保护限制、无意外前台行为、完成后释放资源、可信结果（如有）。缺一项不能把整个适配器标记实测通过。

真实接入前逐份检查连接地址、增强连接索引与启动目标一致；如果存在冲突，应先由用户确认并手动核对，不能直接启动。私有对应表不进入开源仓库。
