# 常见问题与反馈

**新解压后启动提示文件正在使用或 0x80070020？**

管理器加载核心 DLL 前会对共享/锁冲突等待最多约 5 秒。如果占用仍未解除，会明确报错且不启动调度。稍后从同一个完整便携目录再启动即可；不要只复制 EXE。依赖缺失或损坏不会被当作短暂占用重试，应从原 ZIP 重新解压到新目录，并保留已有 data。不要通过关闭安全软件来绕过。

**点立即运行没有启动？**

查看首页等待原因。实例未启用、调度暂停、名额已满、资源残留、接口或绑定未核对都会阻止启动。立即运行不会绕过这些检查。

**退出模拟器后为什么还占位？**

客户端窗口或子进程可能仍在，或者资源探测状态不确定。关闭客户端只是任务退出证据，不是任务成功证据；仅关闭 ADB 端口也不能证明模拟器完全退出。

**为什么管理器重启后需要处理？**

重启后没有上一进程持有的私有 Job 权限。仅凭 PID 和进程名接管可能误杀外部程序，因此保守等待已有任务和资源结束，再由用户核对解除。

**为什么程序更新后不启动？**

入口、程序集或 interface.json 指纹变化。确认新版本的参数与配置兼容后再重新读取适配和核对。不要仅因目录名没变就跳过检查。

**能不能强关所有模拟器来恢复？**

不提供此功能。共享 ADB、模拟器服务及归属不明的资源必须保留。不会执行全局 adb kill-server 或按名称 taskkill。

**为什么 AALC 无法排队自动执行？**

当前核对的版本没有确认可用的无人值守入口；GUI 自身还可能申请管理员权限和操作前台。管理器能真实地发现与观察它，但不会把“打开 GUI 等待点击”包装成自动执行。需要明确的上游协议或另行授权的适配方案。

**便携是什么意思？**

目录可复制迁移，不安装后台服务、不需要源码目录。操作系统仍需 .NET Framework 4.8。外部脚本、框架、模拟器仍由各自原安装提供，不会随包复制。

**如何反馈问题？**

提供管理器版本、Windows/.NET 版本、适配器与客户端版本、复现步骤、预期和实际现象、管理器记录中的事件类型和脱敏原因。不要上传 state.json、账号配置、ADB/设备绑定、令牌、CDK、真实日志、桌面/游戏截图或 VMware 数据。先用可控模拟程序复现更有助于定位。需要日志时只分享经过逐行检查的最小相关片段。
