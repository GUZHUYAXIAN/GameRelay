# 使用说明

## 首次运行

将整个便携目录放到可写位置，不要只复制 EXE。管理器首次启动没有实例或计划。默认只在点击“扫描目录”时扫描 E 盘，扫描深度最多五层，跳过资源、模型、缓存、开发依赖等目录与目录连接。扫描可取消，不会启动发现的程序。深层或被跳过目录请手动添加。

每个安装目录保留独立身份。不要为了多账号把多个安装目录合并。别名只修改显示名称。

## 完成接入

在原脚本界面选择正确设备、任务配置、启动后执行、完成后退出脚本和游戏/模拟器。避免关机、睡眠、链式启动其他客户端或全局 ADB 重启。管理器不修改原脚本配置。

在 GameRelay 脚本页选择“编辑 / 修复路径”：

- 入口必须是安装目录内的 EXE，参数每行一个，不需要自行加引号，也不要写整段 Shell 命令。
- 配置名必须与该客户端实际存在的配置一致。
- 同一模拟器/独占游戏使用同一个目标标识。目标标识只负责互斥，资源探测负责判断是否真正释放。
- MuMu 可绑定原安装的 `MuMuManager.exe` 和单个实例索引；只读 `info -v all` 用来核对该实例是否还在运行。不能凭端口关闭就假定模拟器已释放。
- 本机 ADB 地址与端口用于辅助探测；远程设备不会被当作本机空闲。PC 游戏可以配置其准确 EXE 路径作为残留探测。
- 仅不使用模拟器/游戏资源的自定义进程任务，才可以使用 `process-only:<实例ID>` 并仅按其所属进程树计数。
- 能力核对勾选与真实联调通过不同，不会自动将“真实验证”改为通过。

修改原客户端后，先完成/取消当前队列，在脚本页“重新读取适配”。它保留实例 ID、别名、排序和超时，重新获取客户端配置并恢复停用、待核对状态。修复失效路径不会删除已有计划或账号映射。

## 计划和队列

在脚本页多选实例后点击“批量计划”。时间格式为 `HH:mm`，使用逗号分隔，选择星期与时区。中国的 Windows 时区名为 `China Standard Time`，对应 `Asia/Shanghai`。每个账号保存独立计划和配置名。

创建或修改计划从保存时起计算。停用计划期间不累计新的欠账；重新启用从启用时继续。已有排队不会因修改/删除计划而悄悄消失；需要放弃本轮时在首页选中等待项“取消选中排队”。

启用计划后的离线、睡眠或暂停期间，同一条计划的多次欠账会合并成一轮，保留最早欠账时间排序。不限制离线天数。不同实例、不同计划、不同执行配置分别保留；立即运行与相同配置的已有轮次合并。遇到同一实例已有执行时，其他执行配置等待或要求重新核对。

立即运行也受实例启用、能力核对、暂停、并发上限和目标占用限制。暂停只阻止新的执行与重试，现有任务继续，超时检查仍有效。

## 外部运行、退出与恢复

原目录已有程序存在时保守视作外部运行，即使只是打开窗口也不重复启动。外部运行占普通名额，覆盖这一轮计划后显示“由外部运行覆盖”，不记为成功。

管理器启动时先扫描已有进程，再处理计划。上次管理器启动的任务在重启后也不直接获得清理权限，显示“需要处理”；等待程序及资源结束后，可选择“核对后解除选中阻塞”。仍有资源或状态不明时不能解除。

任务正常退出但模拟器仍存在时继续占位。发生超时/异常时，只清理能够证明属于本轮的进程树；包含 ADB、模拟器服务或安装目录外进程时停止自动清理，要求处理。管理器不调用全局 `adb kill-server`，不会按进程名称批量结束程序。

清理失败、状态不明、资源仍存在都不会叠加重试。清理确认通过后最多重试一次；重试同样排队。第二次失败终止本轮，后续计划仍可触发，但不能越过残留资源。

## 托盘与退出

窗口右上角关闭按钮隐藏到托盘，仍调度。托盘可打开窗口、暂停/恢复、切换鸣潮保护或彻底退出。手动开启鸣潮保护后不会因探测不到鸣潮而关闭。

彻底退出停止后续调度，不杀已运行任务。管理器不创建后台服务。再次运行会重新核对已有进程与资源。

原脚本可能主动抢前台，后台启动参数不能对此作保证。管理器不模拟“开始”按钮、不主动激活游戏窗口。

## 数据迁移与恢复

配置、计划、运行状态、重试次数和事件都在 `data/state.json`，原子替换时保留 `state.json.bak`。设置页可导出备份；备份包含本机路径和绑定，不要公开。

迁移：彻底退出，复制整个便携目录，确认旧目录的管理器已退出，再从新目录打开。外部脚本移动后使用路径修复。

数据损坏：保留原文件、`.bak` 和 `.tmp`。先确认所有旧任务已停止或被外部运行识别，再人工审查恢复文件里的计划游标和运行记录。不要在仍有任务时直接用旧备份覆盖。未知数据版本会阻止启动，不会覆盖文件。

日志只保存管理器事件与固定原因，不收集原脚本日志/环境变量/命令行。保留最近 3000 条事件与历史轮次，仍在等待或处理中者不因上限被删除。
