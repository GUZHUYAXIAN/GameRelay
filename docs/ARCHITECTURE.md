# 架构与扩展

## 模块

- `src/Core`：领域模型、UTC 游标计划计算、队列、并发、目标互斥、外部覆盖和恢复状态机。不依赖 WinForms 或真实进程。
- `src/Infrastructure`：JSON 原子存储、安装发现、客户端核对、Windows 观察与私有 Job Object。
- `src/App`：中文界面、后台命令队列、托盘、扫描取消、计划编辑、日志筛选和通知去重。
- `tests`：确定性时间/进程模拟及真实 Windows 测试进程。与真实游戏分离。

## 启动与故障窗口

一次扫描先核对现有进程与资源，然后生成计划欠账、处理已有运行、提交游标，最后补位。每轮开始前先保存 Starting 意图，再创建挂起的目标进程，将其加入本轮私有 Job，最后恢复执行并保存进程身份。

崩溃发生在创建后、身份写盘前时，重启看到 Starting 会要求处理，绝不当作“没有启动”重跑。正在运行的旧轮次不会仅凭 PID 重获清理权限。保存错误中止整个调度循环。

Job 不设置关闭时杀死子进程，也不继承句柄。管理器退出后没有后台调度服务，已经启动的子进程可以独立收尾。清理只作用于持有的本轮 Job。包含 ADB、服务、VMware、Alas/鸣潮或安装目录外进程时拒绝自动清理，以避免误伤共享资源。

## 状态和时间

Queued → Starting → Running → ExitedUnknown / Succeeded。
Running 遇到残留进入 Residual；超时/明确失败先保存 Cleaning。清理成功且资源释放后进入 RetryQueued（Attempt=1），再次失败变为 Failed。无法可靠清理进入 NeedsAttention。ExternalCovered 与 Cancelled 是终结本轮的独立状态，不属于成功。

计划使用系统时区转换，持久化 UTC ticks。只计算游标之后最早的合法时间点，以一周有界搜索处理任意长离线，而不是遍历每一天。夏令时不存在的本地时间跳过，重复时间采用 .NET 确定性的标准时间映射。回拨不降低游标。新计划以保存时间作为创建边界。

## 适配器扩展

新增适配器应先补充本地版本与官方源码证据、独立配置选择规则、无人值守启动条件、结果证据和资源释放规则，然后加入 Discovery 与 AdapterChecks。未知版本保持待核对，不能把“发现 EXE”自动升级为“可自动执行”。

入口启动使用 argv 数组，经 Windows 命令行引用规则编码后直接调用 CreateProcess，不经 cmd/PowerShell。不要添加 Shell 拼接命令、名称批量结束或全局 ADB 关闭。

实现 `IRuntime` 可以接入测试替身；生产观察返回 ScriptPresent、OwnedAlive、ResourceBusy、Uncertain 等相互独立的事实。只有实现了可信且与本轮关联的结果协议，才可以置 SuccessEvidence。读不到权限/版本/资源信息必须保守阻止补位。

当前不推断历史和未来所有客户端接口，不复制第三方客户端源码，也不预加载框架、OCR或模型。新的协议能力需要相应真实或可控夹具测试。

## 数据版本

当前 Schema=1。未知 schema 拒绝写入，保留用户文件。未来升级应先做独立备份，明确迁移所有 ID、计划游标、重试次数与目标关系，并补齐迁移测试；禁止以空状态覆盖旧版本。
